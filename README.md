# 本地语音转文字工作台

面向中文长音频（讲座 / 会议 / 课程）的**全本地**语音转文字环境：读取 `source/` 目录下的音频，
产出带时间戳的逐字稿，做口语清理与 AI 纠错润色，并提供**音频对照、在线改稿**的网页界面。

全程离线运行，音频与文稿都不离开本机。

---

## 一、模型选型结论（2026-10 实测调研）

| 模型 | 中文 CER | 速度 | 体积 | 结论 |
|---|---|---|---|---|
| **Qwen3-ASR-0.6B (MLX 8bit)** | **7.65%** | ~8.4× 实时 (M4) | 965 MB | **默认主引擎**，中文质量最好 |
| Qwen3-ASR-1.7B (MLX 8bit) | 更低 | 较慢 | ~2.5 GB | 追求极致质量时切换 |
| Fun-ASR-Nano-2512 | 8.59% | 14× (M4 Max) | ~2 GB | 需 GPU，Mac 上不划算 |
| SenseVoice-Small | 10.11% | 58× (M4 Max) | 241 MB | 最快最轻，但中文略差 |
| Whisper large-v3-turbo | ~20% | 46× (M4 Max) | ~1.6 GB | 中文明显更差，不推荐做中文主引擎 |

> 数据来源：FLEURS 中文 945 条真人录音实测（transcribe.cpp / 硅基斥候 S01）、
> FunASR 官方 184 条长音频对比、Qwen3-ASR 官方基准（WenetSpeech CER 6.88 vs Whisper 19.11）。

**本机环境**：Apple M4 / 16 GB / macOS 27，无独显，因此选择 **MLX 原生量化**路线，
不装 PyTorch（省 3 GB 磁盘与大量内存）。

关键能力：
- **Qwen3-ASR**：Apache-2.0，非自回归架构，支持中文 + 22 种方言，长音频按 20 分钟窗口自动切分。
- **Qwen3-ForcedAligner**：非自回归词级强制对齐，把一句话精确落到毫秒，支撑"点句跳播"。
- **Qwen3-8B (MLX 4bit)**：本地 LLM，负责同音错字纠正、去口语、书面化润色、知识库提炼。

## 二、快速开始

```bash
cd voice-to-text-workbench
./setup.sh          # 建虚拟环境 + 装依赖 + 下模型（约 6 GB）
./run.sh            # 启动界面 → http://127.0.0.1:8787
```

把要转写的音频（mp3 / wav / m4a / flac / mp4 …）丢进 `source/` 目录，刷新页面即可。

### 命令行批处理

```bash
# 处理 source/ 下全部音频
.venv/bin/python scripts/transcribe.py

# 只处理一个文件，并直接跑完整后处理链
.venv/bin/python scripts/transcribe.py 周三上午闫树 --rules standard --polish --kb

# 用高精度 1.7B 模型重跑
.venv/bin/python scripts/transcribe.py --engine qwen3-hq --force
```

## 三、处理流程

```
source/*.mp3
   │
   ├─ ffmpeg 转 16 kHz 单声道 WAV
   ├─ silencedetect 静音检测  ──►  语音区间
   ├─ 合并过短块 / 在静音处切分长块（默认 9–30 s）
   │
   ├─ Qwen3-ASR 0.6B 逐块识别 ──► 原文
   ├─ Qwen3-ForcedAligner 词级对齐 ──► 精确句级时间戳
   │
   ├─ 规则层：去口吃重复、删独立语气词、标点规整 ──► 清理稿
   ├─ LLM 层：同音字纠正 + 术语修正 + 去口语 + 书面化 ──► 润色稿
   └─ LLM 提炼：分段要点 → 摘要/要点/术语表 ──► 知识库资料
```

### 时间戳是怎么来的

1. **粗定位**——ffmpeg 静音检测给出语音区间的精确起止秒。
2. **细切分**——Qwen3-ForcedAligner 对每块做词级强制对齐（官方标称时间戳误差降低 67%–77%），
   再按句末标点聚成句子，每句拿到自己的 `start` / `end`。
3. **兜底**——对齐失败时按字符数比例分配时间。

因此界面里每一句都能精确跳转播放，且播放时列表自动跟随高亮。

### 断点续跑与自愈

- 每识别完一块就落盘，中断后重跑只补未完成的部分。
- 续跑时按**时间中点**重新推导段落归属（不信任旧文件里的块号），
  落在块间隙的段落归到最近的块，不会丢内容。
- 每个块还会做**覆盖度校验**：若块内段落缺失或出现异常空隙，该块自动重新识别。
- 每次运行使用独立的临时目录，并发运行不会互相覆盖分块音频。

### 本机实测（Apple M4 16 GB）

| 环节 | 耗时 | 备注 |
|---|---|---|
| 转码 + 静音检测 + 分段 | ~3 min | 2h28m 音频切 534 块 |
| 识别 + 强制对齐 | ~20 min | 约 8.4× 实时，产出 1529 句 |
| 规则清理 | < 5 s | |
| LLM 润色 | ~2–4 s/句 | 批量 16 条/次，可中断续跑 |
| 波形 + 预览音频 | ~1 min | 68 MB 预览 MP3 |

## 四、界面用法

| 区域 | 功能 |
|---|---|
| **顶栏** | 选引擎、开始转写、规则清理、AI 润色全篇、生成知识库、导出 |
| **左侧** | `source/` 目录文件列表与转写状态 |
| **播放器** | 波形图（点击任意位置跳转）、播放/倍速/跟随滚动 |
| **逐字稿** | 每段显示时间戳 + 原文 + 润色稿，**双击段落跳转播放**，单击多选 |
| **编辑** | 直接在格内改字，失焦自动保存；黄色左边框 = 人工修改，绿色 = AI 润色 |
| **单段 AI** | 每段的「AI」按钮只润色该段；「还原」撤销人工修改 |
| **知识库** | 生成的 Markdown 资料，可一键复制 |

耗时任务（润色、知识库）都是**后台执行**：点按钮后立即返回，顶部进度条实时显示
「已润色 N/M 段」，页面可以继续翻稿、继续改稿。

导出格式：`Markdown 整理稿` / `Markdown 原始逐字稿` / `TXT` / `SRT 字幕`。

## 五、目录结构

```
voice-to-text-workbench/
├── setup.sh              一键安装
├── run.sh                启动界面
├── source/               ← 放音频
├── output/<文件名>/
│   ├── audio_16k.wav     转码后的标准音频
│   ├── preview.mp3       浏览器播放用的小体积预览
│   ├── peaks.bin         波形峰值
│   └── transcript.json   逐字稿数据（含人工修改）
├── models/               模型权重
├── app/
│   ├── config.py         配置（全部可用环境变量覆盖）
│   ├── audio.py          ffmpeg 转码 / 静音检测 / 切片 / 波形
│   ├── asr.py            Qwen3-ASR + ForcedAligner 引擎
│   ├── asr_whisper.py    Whisper 备用引擎（多语言场景）
│   ├── align.py          词级对齐 → 句级时间戳
│   ├── textproc.py       口语清理规则层
│   ├── llm.py            本地 LLM 纠错 / 润色 / 知识库
│   ├── pipeline.py       端到端编排 + 断点续跑
│   ├── store.py          JSON 文档存储
│   ├── server.py         FastAPI 接口
│   └── static/           前端界面
└── scripts/
    ├── fetch_models.py   模型下载（curl 断点续传）
    ├── transcribe.py     命令行批处理
    ├── fix_polish.py     校验/修复润色错位
    └── selftest.py       环境自检
```

**断点续跑**：转写进度按块落盘。中断后重新点「开始转写」，已识别的块直接跳过；
还会校验每块的段落覆盖度，缺失或损坏的块自动重识别。润色同理——已润色的段落不重复处理。

## 六、常用环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `STT_SOURCE_DIR` | `./source` | 音频目录 |
| `STT_OUTPUT_DIR` | `./output` | 结果目录 |
| `STT_ASR_MODEL` | `mlx-community/Qwen3-ASR-0.6B-8bit` | 识别模型 |
| `STT_ASR_MODEL_HQ` | `mlx-community/Qwen3-ASR-1.7B-8bit` | 高精度模型（需另行下载） |
| `STT_ALIGNER_MODEL` | `mlx-community/Qwen3-ForcedAligner-0.6B-8bit` | 词级对齐模型 |
| `STT_LLM_MODEL` | `mlx-community/Qwen3-8B-4bit` | 润色模型 |
| `STT_LANG` | `Chinese` | 识别语言 |
| `STT_SEG_MAX` | `30` | 单块最长秒数 |
| `STT_SEG_MIN_MERGE` | `9` | 小于该长度的块会合并 |
| `STT_SILENCE_DB` | `-32` | 静音判定阈值(dB) |
| `STT_PORT` | `8787` | 服务端口 |

> 想让润色走 LM Studio / llama.cpp / Ollama 等任意 OpenAI 兼容服务，
> 设置 `STT_LLM_ENDPOINT=http://127.0.0.1:1234/v1` 即可，无需 mlx-lm。

## 七、后处理说明

### 规则层（快、零成本、可预测）

- 去口吃：`我我我觉得` → `我觉得`、`这个这个` → `这个`
- 删独立叹词：`嗯` `呃` `啊` `额` `哦`（只在独立成词时删，不会误伤「唉声叹气」）
- 删强口水词：`就是说` 等
- 标点规整：合并重复标点、中文间空格清理、保留句末标点

> 「那个」「这个」这类**指示代词**默认不删——它们常常承载语义，
> 交给 LLM 层的上下文判断更安全。

### LLM 层（准、需本地算力）

Qwen3-8B 以「只改不改意思」为硬约束的提示词批量改写：

- 同音字 / 错别字纠正，中文数字转阿拉伯数字（`二零二五年` → `2025年`）
- 专有名词修正（结合上下文判断，例：`minus` → `Manus`）
- 删语气词、口头禅、重复与自我修正痕迹
- 合并碎句、补全标点，保持原有段落意图

批量模式下每批 16 段（实测 1.9 秒/段，比 8 段批量快 30%），输出用**带序号的 JSON 行**
（`{"i": 3, "t": "..."}`）回填——模型偶尔漏写一行也不会让后续条目整体错位；
每条结果还会与原文做字符相似度校验，明显不对应的自动退回原文。
每 96 段落一次盘，中断后重跑只补未润色的部分。

> 跑完可用 `python scripts/fix_polish.py` 复查全篇有没有错位段落，
> 加 `--fix` 直接重润色，加 `--kb` 顺带重建知识库。

### 知识库提炼

长稿走**两段式**：先按 2600 字切块逐块提炼要点，再合并去重，最后按固定结构输出
**标题 / 摘要 / 要点 / 术语表 / 待确认**，适合直接沉淀为内部资料。

## 八、常见问题

**Q: 第一次转写要多久？**
A: 2 小时 28 分的音频，本机实测约 **23 分钟**（8.4× 实时），首次会额外花几分钟加载模型。
之后全部走断点续跑，中断不丢进度。

**Q: 中文数字为什么不直接输出阿拉伯数字？**
A: Qwen3-ASR 不做逆文本归一化（ITN），`二零二五年` 会原样输出。LLM 润色层会统一转换。

**Q: 内存够用吗？**
A: ASR 965 MB + 对齐器 约 1 GB + LLM 4bit 约 4.6 GB，16 GB 机器跑得动。
若只想快速出稿，把 `STT_ASR_MODEL` 指向 0.6B（已是默认）并关掉对齐。

**Q: 网络不通怎么装？**
A: `setup.sh` 默认走阿里云 PyPI 镜像 + HF 镜像。若已有模型目录，`scripts/fetch_models.py`
   支持断点续传，断了重跑即可。

**Q: 能识别方言吗？**
A: Qwen3-ASR 原生支持四川话、粤语、吴语、闽南语、客家话等 22 种方言/口音。
